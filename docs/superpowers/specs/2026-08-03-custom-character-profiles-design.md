# 可配置人物与头像设计

## 目标与范围

提供普通用户无需改 JSON 即可使用的人物设置窗口，支持 1–8 个活跃人物、内置头像、导入本地头像、名称、服装、性格、排序和恢复默认。配置在保存后立即安全应用，重启后保留。高级角色包导入导出留作后续版本，但本次数据模型必须可版本迁移。

## 用户体验

顶部 `🐾` 菜单新增 `人物设置…`。窗口左侧显示可排序人物列表和添加/删除按钮，右侧显示实时预览及以下控件：

- 名称：去除首尾空白后 1–20 个字符。
- 头像：12 个代码生成的原创插画预设，或导入 JPG、PNG、HEIC。
- 本地头像：导入后居中裁切为 512×512 PNG，复制到 Application Support，不再依赖原文件。
- 服装：简约、格纹、外套三种样式，配六套色板。
- 性格：活泼、沉稳、好奇、社交、慵懒五种模板；高级区可调速度、好奇、社交、勇气、困倦五项。
- 排序：上移、下移；新人物默认加入末尾。

人物数量必须为 1–8。达到 8 人时禁用添加；只剩 1 人时禁用删除。编辑发生在草稿中，`保存并应用` 原子写入并重建桌面人物，`取消` 不改变运行状态。

## 默认内容与迁移

新安装默认启用四个非真人角色：橙仔（活泼）、蓝豆（沉稳）、薄荷（社交）、紫团（好奇）。内置头像库共有 12 个不同的脸型、发型和配色预设，服装库有 3 种样式与 6 套色板。

已安装版本首次升级时，若没有用户人物配置，则把现有四个人物和头像迁移成私人本地配置，保持名称、颜色、性格和外观不变。公开发行包不把可识别真人照片作为新安装默认头像。

## 数据与文件

新增版本化 `CharacterRoster(version: 1, profiles: [CharacterProfile])`。每个 `CharacterProfile` 使用稳定 UUID 字符串，包含名称、头像来源、服装样式、色板 ID 和性格。

头像来源为：

- `builtIn(presetID)`：由渲染器确定性绘制。
- `imported(filename)`：只允许安全文件名，解析到应用头像目录内。
- `legacyBundled(identifier)`：仅用于迁移现有本地用户。

配置 JSON 和 `Avatars/*.png` 放在 `~/Library/Application Support/DesktopPets/`。保存使用临时文件加原子替换；头像导入先解码、校正方向、居中裁切、缩放，再写入随机 UUID 文件名。删除或替换后清理不再被任何配置引用的文件。解码失败、名称非法或数量超限时不修改现有配置，并显示明确错误。

## 运行时应用

`AppController` 保存草稿后先验证完整 roster，再停止旧 `WorldRunner`、隐藏旧窗口并创建新 runner。未改变 UUID 的人物保留隐藏/暂停状态；新增人物可见且继续服从全局暂停、隐藏、大小和点击穿透设置。保存失败时旧 runner 不受影响。

菜单和动作改为数量无关文案：`召回全部人物`、`人物管理`、`全部人物一起喊爸爸`。集体动作覆盖当前全部人物。

## 诊断与性能

运行检查不再硬编码四扇人物窗口，而是接受调用方给出的 1–8 期望数量；默认打包自检仍使用四个默认人物。验收必须覆盖 1、4、8 人，8 人仍以 20 FPS 运行且无越界、重复 ID、孤儿窗口或丢失控制入口。

## 测试与验收

- roster 验证：空列表、9 人、重复 ID、非法名称/头像引用均拒绝。
- 版本化存储：默认值、往返、损坏恢复、旧四人迁移和原子失败保护。
- 头像处理：格式解码、512×512 PNG、路径约束、替换与孤儿清理。
- 编辑模型：添加/删除/排序、1–8 边界、模板应用、取消与保存。
- 原生设置窗口：菜单入口、列表、预览、控件状态与保存回调。
- runner 重建：旧窗口全部隐藏，新数量正确，稳定 ID 状态得以保留。
- 动态菜单、集体动作、窗口检查、自检、Release、AddressSanitizer、签名、1/4/8 人运行验证全部通过。
