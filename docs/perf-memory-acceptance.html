2. 发现的问题与根因

#问题根因风险处置
1 Timer 强引用循环泄漏
WorldRunner.start()		 Timer.scheduledTimer(target: self, selector:) 让 Timer 强持有 self，形成 WorldRunner → Timer → WorldRunner 循环，仅依赖 stop() 解环。 高 若某路径未调用 stop()，WorldRunner 及其全部宠物窗口永不释放（内存泄漏）。 已修复
2 通知 Observer 从不移除
StatusMenuController.observeStatusContext()		 注册 3 个通知（didBecomeActive / didChangeScreenParameters / activeSpaceDidChange），但无 removeObserver 也无 deinit。 中 控制器一旦被释放会向野指针发消息（崩溃）；且形成隐式持有。 已修复
3 宠物面板未真正关闭
PetWindowCoordinator / WorldRunner		 roster 切换/退出时仅 orderOut（隐藏），未 close()；窗口可能被窗口服务器持有成为孤儿窗口。 中 多次切换 roster 累积孤儿窗口，长期占用资源。 已修复
4 每帧重复 setRenderScale（空转开销）
PetWindowCoordinator.apply(poses:)		 每个 tick（20fps）对所有宠物无条件调用 setRenderScale，其内部重设 frame、petLayer.bounds 并整层重排反馈层，即便 scale 未变。 中 长期运行下的纯空转 CPU 开销，计入「长时间占用卡顿」隐患。 已修复
5 空闲期仍全速运行 20fps 主循环
WorldRunner.tick()		 即使全局暂停/无交互，主循环每帧仍执行 apply 与 updateMouseAcceptance（坐标转换 + alpha 命中查询）。 低 桌面宠物的固有交互开销；命中查询为 O(1) 数组查表，影响很小。 建议项
