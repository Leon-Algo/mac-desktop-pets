② P3 三大特性实现

特性实现方式核心文件
头像导入 托盘菜单「导入头像…」→ 文件对话框 → WIC 解码为 BGRA（PNG/JPEG/BMP/GIF 首帧）→ 居中裁剪 + 最近邻缩放 512×512 → 纯 Swift PNG 编码 → 经 normalizePNG 闭包注入 CharacterRosterStore，原子写入 %APPDATA%\DesktopPets\Avatars\<uuid>.png；「恢复默认角色」一键清导入回内置。解码炸弹防护与 macOS 一致（25 MB / 8000² 像素上限） AvatarNormalizer.swift、PNGEncoder.swift、Main.swift
托盘动态图标 每 0.8s 按宠物当前帧（PetCanvas 软件光栅当前 pose）重建 32×32 HICON 并 NIM_MODIFY；失败静默保留旧图标；成功后轮换 DestroyIcon 旧图标，杜绝约 2 小时触顶 GDI 句柄上限的泄漏 Main.swift（refreshTrayIcon / currentTrayIcon）
退出后位置恢复 退出时把 leader 锚点 "x,y"（两位小数）写入注册表 HKCU\Software\DesktopPets\SessionState；启动时读回、校验（非有限数/负值拒绝并回退默认布局），按 PetWorld 布局逻辑从锚点重排全部宠物——只存 1 份锚点而非 N 份坐标，天然避免漂移与越界 SessionState.swift、Main.swift

COM vtable 槽位终表（实际调用项，IDL 声明序）：工厂 CreateDecoderFromStream=4、CreateFormatConverter=10；IStream Read=3/Write=4/Stat=12；解码器 GetFrame=13；帧解码 GetSize=3/CopyPixels=7；格式转换器 CopyPixels=7/Initialize=8。绑定按「只声明到最后一个被调用槽位的前缀 + 未用槽位占位」收敛，把签名书写错误面降到最小。

④ 架构：三特性全部下沉纯逻辑层

DesktopPetsCore（跨平台） CharacterRosterStore 扩展 importAvatar / importedAvatarURL / removeUnreferencedAvatars：纯 Foundation 文件操作，图像归一化经闭包注入（macOS 用 NSImage，Windows 用 WIC+PNGEncoder），核心零平台依赖。
WindowsShell 新增纯逻辑 AvatarNormalizer（裁剪+缩放，确定性像素运算）/ SessionState（"x,y" 编解码+校验）/ SessionStatePolicy（注册表键名约定）/ PNGEncoder（纯 Swift PNG 字节生成）。四者 macOS 与 Windows 双端可编译可测试。
平台粘合层（薄） WICSupport：仅保留解码职责的手写 COM vtable 绑定（RAII Release，异常路径不泄漏）；Main.swift：托盘菜单/注册表读写/HICON 重建。全部决策逻辑可在本地断言。

WindowsShell 自检（--self-test）本阶段扩至 9 组断言（新增 avatar 往返 + session 持久化），在 macOS 上即可验证业务逻辑；Windows CI 只需验证「编译 + 平台 API 正确性（COM vtable / 注册表 / GDI）」。纯逻辑单测新增 8 项（normalizer 尺寸映射与拒绝路径、SessionState 往返与非法输入拒绝等），总量 132 → 140。

⑤ 关键决策：PNG 编码去 WIC 化

背景：头像导入需要「像素 → PNG 字节」落盘。首选 WIC 编码器（系统组件，无需自研）。

困境：CI 第 19–24 轮，在槽位经 winapi IDL 序逐项核对、属性袋标准初始化路径、WriteSource 稳定输入全部就位的前提下，frame.Commit 返回 S_OK 而 encoder.Commit 稳定返回 WINCODEC_ERR_WRONGSTATE (0x88982f04)。同一套 vtable 基础设施上解码链路 8 个接口全部真机跑通，独编码路径卡死。

决策：编码是本工程完全可控的格式子集（8-bit RGBA、非隔行、无需压缩率优化）——纯 Swift stored-deflate 实现约 130 行：PNG 签名 + IHDR + IDAT（zlib stored 块）+ IEND，表法 CRC-32（0xEDB88320）+ Adler-32。零平台依赖、确定性输出、双端可全量 XCTest，把风险从 COM 运行时转移到纯逻辑层。

结果：Windows 真机「纯 Swift 编码 → WIC 解码 → 逐像素核对」全绿；macOS 侧同一编码器走签名+IHDR 断言自检。WIC 绑定收敛为 decode-only，代码量净减 55 行（+185/−240）。

⑥ 用户可见行为（Windows 版新增）

  • 托盘右键 → 导入头像…：选一张照片，首位角色立即换脸（自动居中裁剪 512×512，重启后保留）

  • 退出后重新打开，宠物精确回到退出时的位置（注册表持久化，越界/损坏自动回退默认布局）

⑦ 已知遗留（不阻塞验收）

  • WIC 编码器 WRONGSTATE 的底层根因（WIC 内部状态机 vs 手写 vtable 交互）未继续深究——纯 Swift 方案已绕开，且编码格式子集完全可控，无回归风险面
  • 托盘动画刷新率固定 0.8s：与宠物世界模拟步长对齐，如需更细腻可调，当前无需求
  • Swift 6.0.3 ASan 编译器瞬时崩溃（P2 已记录的上游工具链问题）本轮未复发，若复发按 P2 结论处理（固定 setup-swift 6.1+ 或 CI 自动重试）
