③ 过程中修复的 bug 与踩坑

#问题修复
BUG Y 轴映射埋底 120px（v0.2.0 遗留）：原 maxY - y - 20 把窗口高度（100）与地面偏移（20）混算，宠物实际悬浮在地面上方 120px。修正为 originY = displayBottomY - petY - (windowHeight - 1) - groundOffset，自检断言 origin.y == 901 钉死精确值，杜绝回归。
CI-1Swift 6 严格并发：全局 delegate / 枚举上下文不可捕获进 C 函数指针文件级 nonisolated(unsafe) var（单线程消息循环内安全）
CI-2swift-win-sdk 回调句柄是 Optional（HWND?/LPRECT?）回调参数声明为 Optional，handleMessage 统一解包
CI-3NOTIFYICONDATAW.szTip 是 128-WCHAR tuple，不能作 KeyPath按 x64 C 布局固定偏移 40 手写字节写入
CI-4CreateIconIndirect 要求 hbmMask 非 NULLCreateBitmap 1bpp 单色掩码 + 32bpp BI_RGB DIB 颜色位图
CI-5SDK 把 BOOL 返回盲桥接为 Swift Bool（Shell_NotifyIconW / TrackPopupMenuEx / EnumDisplayMonitors 回调）去掉 != 0 与 TPM_RETURNCMD 依赖；托盘菜单改自然 WM_COMMAND 路由 + WM_NULL 唤醒模态循环
CI-6MAKEINTRESOURCEW 是 C 宏，Swift 无符号等价展开 (LPWSTR)(INT_PTR)id → UnsafePointer<WCHAR>(bitPattern: 32512)
CI-7Swift 6.0.3 ASan 编译瞬时崩溃（LLVM RegisterBankInfo 断言 signal 6，run 33319202276）确认为编译器自身 bug：Unit tests 步骤同轮已绿、diff 不含 macOS 路径、30 分钟前同源码刚绿。空提交重触发后通过（run 33319540394）

④ 架构：纯逻辑跨平台自检模式

DesktopPetsCore（跨平台） PetWorld / PetCanvas / 交互语义 / 名册持久化。纯 Foundation，双端编译。CoreProbe 无头自检：确定性 + 2h 长时 + 交互 + 持久化。
WindowsShell 新增纯逻辑层 MonitorLayout（多显示器布局）/ PointerModel（手势状态机）/ ScreenBridge（坐标互转）/ AutostartPolicy（自启命令与注册表分离）。全部纯 Foundation，可本地断言、CI 复跑。
Main.swift（Win32 粘合） 消息循环 / wndProc 路由 / 托盘 / 菜单 / 注册表 / DIB→HICON。仅薄薄一层 API 调用，全部决策逻辑下沉纯逻辑层。

WindowsShell 自检（--self-test）7 组断言：渲染、坐标桥、600 帧长时、渲染确定性、hex 配色解析、PointerModel 手势、交互语义 + 多显示器 —— 在 macOS 上即可验证 Windows 壳的业务逻辑，Windows CI 只需验证「编译 + 平台 API 正确性」。

⑤ 用户可见行为（Windows 版）

  • 解压 zip 双击 DesktopPets.exe 即用；首次启动 SmartScreen 提示「更多信息 → 仍要运行」
  • 宠物行走在任务栏上方地面；点击宠物有反应（单击问候），拖拽可搬运，松手下落
  • 透明像素区域点击穿透到下层窗口，只有宠物本体可交互
  • 托盘右键：开机自启（勾选开关）/ 退出桌面伙伴
  • 显示器热插拔 / 分辨率变化（WM_DISPLAYCHANGE）自动把宠物召回有效屏幕

⑥ 遗留事项（P3，不阻塞验收）

  • macOS 侧尚未提供 code signing / notarization（Gatekeeper 右键打开可用，README 已说明）；Windows 侧无 Authenticode 签名（SmartScreen 提示同理）
  • Windows CI 的 Swift 6.0.3 ASan 瞬时崩溃为上游工具链问题，若复发可考虑固定 setup-swift 到 6.1+ 或在 CI 加一次自动重试
  • 托盘图标当前为静态头像，未随宠物动作帧更新（可作后续小特性）
